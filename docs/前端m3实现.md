## 1. 已做什么（会话管理 + 参数面板 + 轻量可观测性）

### A. 会话管理

- **组件** `src/components/SessionList.vue`：左侧栏（M2 预留位），新建/切换/重命名（ElMessageBox.prompt，空标题前端拦截）/删除（ElMessageBox 确认）；生成中拦截切换/删除/新建，避免流式写入串会话
- **store** `src/stores/session.ts`：扩展为「列表 + 当前会话 + 当前消息」完整态；`loadSessions`（启动时加载并恢复 updated_at 最新会话）、`createSession`（立即 POST 空会话并选中）、`openSession`（拉消息填充聊天区）、`applyChatMeta`（chat meta 帧回填 session_id/title，自动命名后列表同步置顶）
- **SESSION_NOT_FOUND 兜底**：打开/重命名/删除/chat 各路径捕获后提示「请新建会话」，从列表剔除并清空当前视图（`handleSessionGone`）

### B. 参数面板

- **组件** `src/views/ParamsView.vue`：右侧 el-drawer，ChatView 顶栏「参数」按钮进入；5 个滑块（标注后端校验范围）+ system prompt 多行 + 三预设按钮（精确/平衡/创意）
- 预设值与校验规则逐字对齐 `server/params/presets.py`；修改任一采样参数即显示「当前：自定义」；点预设只填表单，保存时才 PUT
- PUT 只发 6 个显式字段、**不发 preset**（值命中预设时服务端自动标名；`preset: 'custom'` 传过去会被当未知预设拒 400）；后端 400 的 message 经 ElMessage 提示
- 打开抽屉/应用启动均 GET 初始化到 `src/stores/settings.ts`

### C. 轻量可观测性（PRD 3.4 轻量版）

- 生成中输入框上方实时显示 `生成中 · X token/s`：token 帧数 /（当前时刻 − 首 token 时刻），实现在 `useChatStream`
- 每轮 done 后同位置显示 `上下文占用 input_tokens / (n_ctx - max_tokens) tokens（%）`；`n_ctx=8192` 为前端常量 `MODEL_N_CTX`（stores/settings.ts，注释标注来源 server/config.py，后端暂无查询接口）；≥80% 时追加警告「上下文将满，建议开新会话」
- 调试抽屉 Token 统计标签页未动（历史消息无帧数据时 el-empty 兜底）

### D. mock 层（VITE_API_MODE=mock 默认）

- `src/api/mock.ts` 重写：会话/消息/参数用 localStorage 持久化（键 `fkjsllm.mock.sessions` / `fkjsllm.mock.params`），模拟后端重启不丢
- 行为对齐后端契约：空会话首条消息前 20 字自动命名；EMPTY_TITLE / INVALID_PARAMS / SESSION_NOT_FOUND 错误码一致；参数 preset 服务端展开 + 显式字段优先 + custom 匹配逻辑与 `presets.save()` 相同；停止生成部分结果保留

## 2. 契约对齐情况（对照后端m3实现.md §2）

| 契约 | 前端落点 | 状态 |
| --- | --- | --- |
| GET /api/sessions（倒序） | `client.listSessions` / mock；启动时加载 | ✅ |
| POST /api/sessions {title?} | `client.createSession`；「新建」立即调用并选中 | ✅ |
| GET /{id}/messages | 切换会话时拉取填充 | ✅ |
| PATCH /{id}（空标题 400 EMPTY_TITLE） | 前端 inputValidator 先拦，后端 400 提示 message | ✅ |
| DELETE /{id}（级联） | ElMessageBox 确认后删除，当前会话被删则切剩余最近或清空 | ✅ |
| 409 SESSION_NOT_FOUND | 全路径兜底：提示 + 清视图引导新建 | ✅（代码走查，mock 难构造真 409 时序） |
| GET/PUT /api/params | 打开抽屉 GET；保存 PUT 补丁；INVALID_PARAMS 提示 message | ✅ |
| chat meta 帧 session_id/title 回填 | `applyChatMeta` 同步列表 | ✅ 实测（自动命名后列表即时更新） |
| done.usage → 上下文占用 | `lastUsage` + `contextBudget` | ✅ 实测（mock 显示 121/6144） |

**契约偏差记录**：后端 400 错误体是 FastAPI 默认的 `{"detail": {code, message}}`（HTTPException 包装），与 409 的顶层 `{code, message}`（ServiceError 全局处理器）结构不同。`client.ts parseErrorBody` 已兼容两种形状——这是本次发现的契约坑，real 联调时若 400 提示不显示先查这里。

## 4. 坑点（新增）

1. **FastAPI 400 错误体有 `detail` 包装**：`HTTPException(400, {...})` 的实际响应是 `{"detail": {"code","message"}}`，不是顶层平铺；409（ServiceError handler）才是平铺。前端解析错误体必须兼容两种形状（已在 `parseErrorBody` 处理）
2. **`preset: 'custom'` 不能回传后端**：后端只认 precise/balanced/creative，custom 是「不命中任何预设」的推导结果而非可选项；PUT 只发显式字段，预设名让服务端自行匹配
3. **后端重命名不推进 updated_at**：PATCH 后列表顺序不变，前端原位更新标题即可，无需重排
