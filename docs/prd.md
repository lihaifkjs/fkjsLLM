# PRD：LLM全流程

> 状态：待评审 | 日期：2026-10-07
> 目标：在 Windows（RTX 4070 12GB）上运行一个 Web 图形界面的本地 LLM，支持局域网内多设备（Mac / iPhone / Android 浏览器）访问。

## 1. 背景与目标

- 已下载模型：Qwen3-14B-Q4_K_M.gguf（约 9GB，可基本全量 GPU offload）
- 一期目标：MVP——纯对话 + 推理参数 + 局域网 Web 访问 + 移动端响应式 UI
- 二期方向（本期不实现，仅预留扩展位）：RAG 知识库、联网搜索、语音、公网访问、多账号体系、可观测性面板、模型闲置自动卸载

## 2. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 推理后端 | llama-cpp-python | 直接加载 gguf，支持 GPU offload |
| API 框架 | FastAPI | REST + SSE 流式输出 |
| 数据库 | SQLite | 会话与消息持久化，零部署 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router | 官方全家桶 |
| 部署 | 单进程：uvicorn 托管 API + 前端静态文件 | 手机访问 http://<PC_IP>:8000 |

## 3. 一期功能需求

### 3.1 对话（核心）

- 多轮对话，上下文由后端拼接管理
- **流式输出**（SSE），前端逐字渲染
- 停止生成（中断当前推理）
- 重新生成（基于同一上下文再答一次）
- 编辑已发送的用户消息并重新发送（截断其后消息）
- Markdown 渲染（含代码块高亮），对话气泡式 UI

### 3.2 会话管理

- 左侧会话列表：新建、切换、删除、重命名
- 历史记录持久化（SQLite），刷新/重开不丢
- 按首条消息自动生成会话标题（调用模型摘要，失败则取前 20 字）

### 3.3 推理参数面板

- 可调参数：temperature、top_p、top_k、repetition_penalty、max_tokens
- 系统提示词（system prompt）编辑框，支持保存为自定义模板
- 内置预设：精确（temp 0.1）/ 平衡（0.7）/ 创意（1.0），一键切换
- 参数按会话生效或设为全局默认值（全局优先，一期只做全局）

### 3.4 模型状态展示

- 流式生成时实时显示 token/s
- 服务启动时打印/接口返回显存占用、上下文长度、模型加载状态
- 上下文剩余空间提示（超限时告警，提示开新会话）

### 3.5 多端访问

- 响应式布局：桌面双栏（会话列表 + 对话区），移动端单栏（抽屉式会话列表）
- 输入框适配手机软键盘
- 监听 0.0.0.0，局域网内任意设备浏览器直接访问

### 3.6 账号（本期仅占位）

- 配置文件预留 `AUTH_ENABLED` 开关（默认 false），一期不做实现

### 3.7 可观测性面板（本期仅占位，前端预留）

- **本期不实现任何可观测性功能，但前端必须预留结构**：每条消息（或每轮对话）提供可展开的「调试抽屉」，内部为标签页容器。
- 抽屉标签页一期全部以占位内容渲染：统一显示默认值「未实现」，接口字段返回空值即可。
- 预留的标签页（即二期候选内容）：
  1. Prompt 预览：完整模型输入（system prompt、历史、tools 定义）按角色着色渲染
  2. Token 统计：每轮输入/输出 token 数、各段占比（system/历史/当前消息）
  3. 调用链：工具 / MCP 调用的原始请求、执行结果、拼回上下文的过程
  4. 性能指标：首 token 延迟（TTFT）、token/s、prefill/decode 耗时
  5. 生效参数快照：该条消息实际使用的推理参数
- **设计要求**：新增一个标签页只允许「加配置 + 写组件」，不允许改动抽屉容器与消息列表的结构。

### 3.8 模型加载开关（随用随加载，不常驻内存）

- 模型默认不加载，前端提供「加载 / 卸载」开关，避免长期占用约 10GB 显存/内存（使用频率低，随用随加载更划算）
- **状态机**：未加载 / 加载中 / 已加载 / 卸载中 / 错误，前端按状态渲染控件，加载/卸载过程中禁止重复操作
- **加载反馈**：加载耗时较长（首次从磁盘读 9GB，约数十秒），前端必须显示加载中状态与提示，避免误判卡死
- **未加载时的行为**：聊天输入框禁用并提示「请先加载模型」
- **生成中禁止卸载**：须先停止生成；接口层做保护，非法操作返回明确错误
- **参数与加载解耦**：修改 temperature 等推理参数不触发重新加载；仅模型路径、offload 层数等加载期配置影响加载
- **接口**：`GET /api/model/status`、`POST /api/model/load`、`POST /api/model/unload`
- 二期：闲置自动卸载（如 30 分钟无请求自动卸载）

## 4. 非功能需求

- 单用户为主，偶尔 1-2 人同时使用；不做并发会话隔离，共享同一模型实例
- 首 token 响应 < 3s（GPU 全 offload 前提下）
- 代码质量：高内聚低耦合，模块职责单一；README 提供启动与验证方法

## 5. 架构草案

```
浏览器（桌面/手机）
   │ HTTP / SSE
   ▼
FastAPI（单进程）
   ├── /api/chat（SSE 流式）
   ├── /api/sessions（会话 CRUD）
   ├── /api/params（推理参数）
   ├── /api/model/status|load|unload（模型加载开关）
   └── 静态文件（前端 build 产物）
   │
   ├── llama-cpp-python（模型实例，进程内单例）
   └── SQLite（sessions / messages / settings 三张表）
```

## 6. 里程碑

1. **M1**：后端跑通——加载模型，SSE 流式对话接口可用（curl 验证）
2. **M2**：前端对话界面——桌面端完整可用
3. **M3**：会话管理 + 参数面板
4. **M4**：移动端响应式适配 + 联调验收

## 7. 明确不做（一期）

- RAG / 联网搜索 / 语音
- 公网访问与内网穿透
- 多账号体系、权限
- 多模型切换（单模型写死配置）
- 对话分支树
- 可观测性面板的具体实现（仅按 3.7 预留结构，占位渲染）
