## 1. 目标

- 同一 prompt 用 2–3 组参数（temperature / top_p / top_k / max_tokens）生成，多栏并排展示结果
- 前端串行发请求（单模型实例约束），UI 表达「排队中 / 生成中 / 完成 / 失败 / 已停止」状态
- 每组结果可展开查看观测数据：分段 token 统计、TTFT/prefill/decode、参数快照（M5 口径）
- 实验结果独立存储（experiments + experiment_runs 新表），不写入正式会话历史；刷新后历史实验可查

## 2. 现状盘点（2026-10-10 调研结论）

**后端**：
- `model_manager.generate(messages, params)` 与会话解耦，单轮实验可直接复用；`GenerateResult` 已含 M5 全部观测字段（prompt_text / prompt_messages / seg_tokens / ttft_ms 等）
- 观测落库汇合点在 `chat/engine.py::_wrap`（finally 回填，含 stop 中断路径）——实验编排需要同款汇合逻辑
- 全局生成锁保证单路生成；实验与正式对话互抢锁时后者返回 409（需定义错误码行为，见决策 D）
- messages 表 M5 已加 7 个观测列，experiment_runs 照搬同口径列；迁移沿用 `PRAGMA user_version`（当前 v1 → v2）
- 参数校验逻辑在 `params/presets.py`（temperature ≥ 0 等），实验参数直接复用

**前端**：
- 路由现有 ChatView 单页；新增 `/lab` 路由无历史包袱
- 参数滑块与校验范围在 `ParamsView.vue`，字段与后端逐字对齐，可抽取复用
- SSE 解析封装在 `useChatStream`（fetch + ReadableStream），实验流需同款循环但写入目标不同（写 run 而非会话消息）——抽公共解析函数还是各写一份，实现时定（倾向抽 `api/sse.ts` 共用帧解析）
- `useObservability` 绑定「session_id + message_id」，实验 run 不走该通道；观测数据随实验详情接口下发（见决策 B）
- mock 层 localStorage 持久化模式成熟（`fkjsllm.mock.*`），实验数据照此办理

## 3. 数据存储（SQLite，app.db 迁移 user_version 1→2）

```sql
CREATE TABLE experiments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  prompt TEXT NOT NULL,
  system_prompt TEXT NOT NULL DEFAULT '',  -- 创建时的全局 system prompt 快照
  created_at REAL NOT NULL
);

CREATE TABLE experiment_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  experiment_id INTEGER NOT NULL REFERENCES experiments(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,                  -- 栏位顺序 0/1/2
  params TEXT NOT NULL,                  -- JSON {temperature, top_p, top_k, max_tokens}
  status TEXT NOT NULL DEFAULT 'pending',-- pending/running/done/stopped/error
  content TEXT NOT NULL DEFAULT '',
  error TEXT,                            -- 失败时的 {code, message} JSON
  created_at REAL NOT NULL,
  finished_at REAL,
  -- 观测列，与 messages 表 M5 口径一致
  input_tokens INTEGER, output_tokens INTEGER, prompt_eval_tokens INTEGER,
  prompt_text TEXT, prompt_messages TEXT, prompt_seg_tokens TEXT,
  ttft_ms REAL, prefill_ms REAL, decode_ms REAL
);

CREATE INDEX idx_runs_experiment ON experiment_runs(experiment_id, seq);
```

## 7. 决策记录（2026-10-10 已确认）

- **A. 入口形态**：新增独立路由 `/lab`，不改 ChatView 结构
- **B. 存储**：experiments + experiment_runs 两张新表完全隔离；观测数据随 `GET /api/experiments/{id}` 详情下发（不开独立 observability 端点——run 数据量小，一次取全）
- **C. 排队机制**：前端串行发请求，每栏独立 SSE；后端不建任务队列
- **D. 参数范围**：temperature / top_p / top_k / max_tokens 四项；system prompt 取创建时全局值并快照入 experiments 表（实验间可比性），repetition_penalty 用全局当前值
- **E. 与正式对话互抢锁**：generate 遇全局锁占用返回 409 `GENERATION_BUSY`，前端该栏标失败并允许重试（不重排队列）
- **F. 上下文**：实验为单轮（system + 当前 prompt），不走滑窗；超长直接报 `PROMPT_TOO_LONG`

## 8. 风险与坑点

- **观测回填汇合点**：`lab/engine.py` 必须复刻 `chat/engine._wrap` 的 finally 模式（正常/stop/异常三路径），漏一路径 run 观测字段即残缺
- **帧协议复用**：generate 的 SSE 帧型与 chat 完全一致（meta/token/done/error），前端帧解析若各写一份会漂移——抽公共解析或显式声明两处同步点（5.1 实现时定）
- **run 状态恢复**：刷新时 running 状态的 run（后端实际已断）需在详情接口读取时纠正为 error/stopped，否则前端永久显示「生成中」
- **mock 自洽**：实验 mock 的观测假数据沿用 M5 `buildObservability()` 约束；不同参数组输出长度应有差异（max_tokens 截断生效），否则教学对比失真
- **400 错误体 detail 包装**：M3 坑点同形状，`parseErrorBody` 已兼容，新增端点错误码沿用即可
- **私有 API 依赖**：观测字段来源同 M5（`_ctx` / `llama_perf_context`），绑定 llama-cpp-python 0.3.36，不重验
