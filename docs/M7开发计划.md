## 1. 目标

- 文档管理最小集：上传 / 列表 / 删除，独立路由页 `/knowledge`（无详情页）
- 检索注入：会话开启开关后，每轮用当前 user 消息检索知识库，命中片段以独立 system 段注入 prompt
- 可观测：检索落库（query/命中片段/相似度/耗时），调用链标签页展示；注入段在 Prompt 预览天然可见
- 降级哲学与 M6.5 一致：检索/embedding 异常不阻断对话，整体降级为不注入

## 2. 现状盘点（2026-10-11 调研结论）

**后端**：
- 上下文拼装的唯一分流点在 `chat/engine.py::_build_prompt`（M6.5 已在此按 `context_strategy` 分流滑窗/摘要）——检索注入挂在策略分流**之前**，与两策略正交

## 3. 数据存储（SQLite，app.db 迁移 user_version 3→4）

```sql
CREATE TABLE documents (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  filename TEXT NOT NULL,
  content TEXT NOT NULL,            -- 原文落库（排障/教学可直接查库，不做 UI）
  char_count INTEGER NOT NULL,
  chunk_count INTEGER NOT NULL DEFAULT 0,
  created_at REAL NOT NULL
);

CREATE TABLE chunks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  document_id INTEGER NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  seq INTEGER NOT NULL,             -- 文档内顺序
  content TEXT NOT NULL,
  char_count INTEGER NOT NULL,
  embedding BLOB NOT NULL,          -- float32 小端字节流，dim=512
  created_at REAL NOT NULL
);
CREATE INDEX idx_chunks_document ON chunks(document_id, seq);

CREATE TABLE retrievals (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  trigger_message_id INTEGER NOT NULL,  -- 本轮 assistant 占位消息 id（关联调用链）
  query TEXT NOT NULL,
  hits TEXT NOT NULL,               -- JSON 快照 [{chunk_id, document_id, filename, score, content}]
  injected_tokens INTEGER,          -- 注入段 token 数（count_tokens 口径）
  latency_ms REAL,                  -- query embedding + 全表扫描耗时
  created_at REAL NOT NULL
);
CREATE INDEX idx_retrievals_session ON retrievals(session_id, id);

ALTER TABLE sessions ADD COLUMN rag_enabled INTEGER NOT NULL DEFAULT 0;
```

- `hits` 内嵌命中片段**快照**，不回联 chunks——文档删除后历史调用链仍可查看
- 文档是全局池，不属任何会话；删会话级联 retrievals，删文档级联 chunks、不动 retrievals
- 上传同步处理，失败直接报错不落库，故 documents 无 status 列

## 4. 检索注入设计（chat 层）

**模块划分**：新增 `server/rag/`——`chunker.py`（切块纯函数）、`embedder.py`（embedding 实例管理，独立 CPU 推理栈）、`retriever.py`（相似度扫描）、`ingest.py`（文档入库编排）。分层约束：api → rag（文档管理）；chat → rag（检索）；rag → session_store。embedder **不经过** model_manager（那是 14B chat 模型单例）。

**检索流程**（`engine._build_prompt` 内，策略分流之前）：
1. `session.rag_enabled` 且库内有文档 → `retriever.search(query=当前 user 消息 content)`
2. query 加 bge 指令前缀后 embedding → 全表 chunks 余弦相似度（先 L2 归一化）→ 阈值过滤 + Top-K
3. 有命中 → 拼注入段：独立 system 消息（`RAG_PREFIX` 前缀可辨识，各片段带来源标注「[文档: xxx]」）；落库 retrievals
4. 无命中 → 也落库（`hits=[]`），不注入
5. 异常 → 降级不注入，不落库，对话继续（决策 I）

**上下文顺序**：system prompt → RAG 注入段 → 摘要段（若有）→ 历史 → 当前输入。注入段**不参与**滑窗/压缩截断，自身设 token 上限（超出则按分数从高到低减片段数）；注入段计入 budget，挤压历史触发截断/压缩属预期教学效果。

**常量**（`server/config.py`，spike 定值）：`RAG_CHUNK_SIZE`（初值候选 500 字）、`RAG_CHUNK_OVERLAP`（50）、`RAG_TOP_K`（3）、`RAG_SCORE_THRESHOLD`（余弦，初值候选 0.45）、`RAG_MAX_INJECT_TOKENS`（512）、`RAG_UPLOAD_MAX_BYTES`（256KB）、`RAG_QUERY_PREFIX`（bge 检索指令前缀）。不暴露给用户面板（同 M6.5 决策 F）。

**等待体验**：检索在主生成前同步执行（CPU embedding 预计百毫秒级），无新增 SSE 事件，耗时计入 TTFT 并在调用链展示（同 M6.5 决策 G）。

## 10. 决策记录（2026-10-11 已确认）

- **A. pdf 不做**：本期仅 txt/md；pdf 解析待后续评估（PRD 口子关闭）
- **B. embedding 模型**：bge-small-zh-v1.5，走 CPU；推理栈 spike 二选一（GGUF via llama-cpp 优先试，fastembed 备选）
- **C. 组织粒度**：单知识库全局文档池 + 按会话开关（sessions.rag_enabled，默认关）
- **D. 管理界面**：独立路由页 `/knowledge`，只做上传/列表/删除，无文档详情与切块查看页
- **E. 注入形式**：独立 system 段（`RAG_PREFIX` 可辨识），位于 system prompt 之后、摘要/历史之前；不参与截断，设 `RAG_MAX_INJECT_TOKENS` 上限
- **F. 常量而非参数**：切块/Top-K/阈值/注入上限为 config 常量（spike 定值），面板只暴露会话开关
- **G. 无新增 SSE 事件**：检索在生成前同步执行，耗时计入 TTFT，调用链展示
- **H. 检索记录独立 retrievals 表**：hits 内嵌快照 JSON，与文档生命周期解耦；observability `retrieval` 字段两态（启用→记录 / 未启用→null）
- **I. 降级不阻断**：检索/embedding 异常 → 不注入、不落库、对话继续（同 M6.5 双兜底精神）
- **J. mock 最小桩**：按 2026-10-11 规约，行为流程统一 real 联调验证
- **K. 精简范围（2026-10-11）**：只保留核心 RAG 链路 + 调用链观测；砍掉文档详情/切块查看页、documents.status 列（上传同步处理，失败不落库）

## 11. 风险与坑点

- **bge 检索前缀**：query 侧漏加指令前缀检索质量骤降；document 侧不加。spike 有/无对照实证
- **归一化**：bge 输出未 L2 归一化时余弦分数失真；入库与 query 两侧都必须归一化
- **GGUF pooling**：llama-cpp 加载 embedding GGUF 需确认 pooling 方式正确（bge 用 CLS pooling），spike 对拍 fastembed 输出向量余弦 ≈1 可证等价
- **向量序列化**：BLOB 存 float32 小端，反序列化用 `array`/`struct` 零依赖即可，不为此引入 numpy
- **CPU 争用**：当前 14B 跑 CPU 版（`n_gpu_layers=0`），检索与主生成串行无争用；embedding 模型常驻内存 ~百 MB 可接受
- **编码**：上传仅接受 utf-8 可解码文本，GBK 文件 400 `INVALID_ENCODING`（不做隐式转码）
- **预算挤压**：注入段计入 budget 会使长会话更早触发截断/压缩——预期教学效果，但需在 Prompt 预览可辨识（前缀已实现）
- **幂等**：重复上传同名文件不去重（允许并存，文件名不代表内容）；删文档后 retrievals 快照仍可读（决策 H）
- **检索时序**：retrieval 落库依赖 assistant 占位消息 id，检索必须发生在占位插入之后、主生成之前——与压缩同窗口，注意编排顺序
