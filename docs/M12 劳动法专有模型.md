# M12 劳动法专有模型：「知识走 RAG、能力走权重」的完整落地

> 日期：2026-10-17 | 状态：方案待评审 | 定位：demo——让人看懂专用模型在专业项目里到底哪里有用
> 前序：M7（RAG 知识库）、M8（QLoRA + 多模型注册表）、M11（SFT 再训练，并行进行）
> 范围：本文只讨论「劳动法」单一领域

## 1. 目标与定位

一句话：**在同一知识库、同一题集下只换模型**，证明领域 SFT 让法律问答"会用资料"，而知识本身留在 RAG 里。

"专"拆成两层（demo 要讲清的核心）：

- **知道什么**（法条事实）→ RAG：可增量更新、可溯源、逐字准确
- **怎么用**（引用纪律、分档推理、术语表达、边界拒答）→ 权重：只能靠 SFT

不追求"模型记住法条"——闭卷答对反而视为训练集泄题的告警信号（见 §7.3）。

## 2. 决策记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| A | 法条知识全部走 RAG，SFT 不背事实 | 法条要求逐字准确 + 可溯源 + 会修订；LoRA 容量与幻觉风险都不划算 |
| B | 引用用运行时序号 `[1][2]`，不让模型生成条文号 | 编号变成运行时数据，机制上消除"记忆型幻觉"；同时避免 shortcut learning |
| C | 训练与推理两侧的 context 渲染必须同源 | 训练教 `[1]`、线上注入没编号 → 格式立刻崩（最高优先级坑） |
| D | think 口径：开卷作答带 think；拒答/边界带**极短判定 think**（30–60 字） | 2026-10-17 修正（原为「拒答不带 think」）：Qwen3 模板对末条 assistant 强制预开空壳，空壳样本等于教模型关思考——M11 §2.1 实锤（950 条空壳 × 4 epoch 把 think 训死）。故拒答也给一段判定过程再直答 |
| E | 首版不做 query 改写 | 加一轮 LLM 调用会改 chat 编排；先用召回指标实测（§4.3） |
| F | 首批范围只《劳动合同法》+《实施条例》 | 136 条足以覆盖高频场景，语料公开、生命周期稳定 |
| G | 前端零改动，`[1]` 以纯文本显示 | 来源可在 M5/M7 调试抽屉的检索区块查看；渲染成链接列为可选增强 |
| H | M12.1/M12.2 不依赖 M11，先行开工 | 知识库与题集不需要新模型；M12.4 才需要基座 |

## 3. 方案总览

```
用户提问
  │
  ├─(1) 检索：按"条"切块的 chunks → top_k → [1]《劳动合同法》第十九条…
  │
  ├─(2) 注入：context 按固定格式拼入 prompt（与 SFT 渲染同源）
  │
  ├─(3) 生成：law-14b（领域 SFT）→ 结论 + 分档条件 + [n] 引用 + 免责
  │
  └─(4) 观测：retrievals 落库 → 调试抽屉可见召回片段与相似度
```

## 4. 知识库设计

### 4.1 语料与切块

- 语料：《劳动合同法》98 条 +《实施条例》38 条 = 136 条
- **一条 = 一个 chunk**：改 M7 切块器支持「按条切块」模式（行首 `第X条` 为分隔符），法律语料走该模式，既有文档行为不变
- 条号以文本前缀保留（`《劳动合同法》第十九条：<原文>`），不依赖 chunks 表 schema 变更，免 user_version 迁移
- 超长条（>512 token）按款再拆，拆分后前缀带款号

### 4.2 注入格式（契约，必须与训练样本逐字一致）

```
[1] 《劳动合同法》第十九条：<原文>
[2] 《劳动合同法》第八十三条：<原文>
```

- 编号由注入层按检索顺序生成（M7 现为纯片段拼接，需加编号）
- 现有注入预算 512 token、相似度阈值 0.40 均为 M7 按原切块调定 → **按条切块后需重标定**

### 4.3 检索质量先验指标（决定决策 E）

- 用 20 条口语化问题实测 top-3 命中对应条文的比例
- >70% → 首版不做 query 改写；<70% → 追加一轮 query 改写（复用 M9 两轮编排模式），M12 范围相应扩大并重新评审

## 5. SFT 语料设计

### 5.1 契约

一行一 JSON；`context` 为模拟检索结果，渲染时复用服务端注入函数：

```json
{"category":"law_grounded_qa","system":"<领域角色>","context":[{"ref":1,"title":"《劳动合同法》第十九条","text":"<原文>"}],"question":"...","answer":"<think>...</think>\n\n... 依据《劳动合同法》第十九条[1]，..."}
```

**引用写法（2026-10-17 定）**：行内带出处——`《劳动合同法》第十九条[1]`。
只写 `[1]` 不写标签视为违规；标签必须与注入材料里该编号的标签逐字一致。
理由：读者不懂 `[1]` 指什么；行内写法在答案被截断时也不会丢出处（末尾清单会先被截掉）。
代价：模型必须"抄"标签，故判分新增「标签一致性」与「引用无出处」两项兜底（§7.2）。

### 5.2 四类样本

| category | think | 数量 | 关键约束 |
| --- | --- | --- | --- |
| `law_grounded_qa` | 带 | 200 | 答案中每个 `[n]` 必须能在本样本 context 找到，且前面紧跟同编号的条文标签 |
| `law_insufficient` | 短 think（判定缺什么） | 60 | context 空 / 不相关 / 缺关键条 → 明说缺什么 |
| `law_scope_refuse` | 短 think（判定超范围） | 40 | 超范围（诉讼策略、其他法域）→ 拒答 + 转介 |
| `law_multiturn` | 带 | 80 会话（展开≈200 样本） | 会话内事实一致；按 M11 前缀展开 |

三类范本（口吻与结构以此为准）：

- **开卷作答**：结论（合法/不合法/需分情形）→ 依据（`《劳动合同法》第十九条[1]`）→ 适用条件 → 可主张措施 → 免责
- **诱导幻觉**：用户抛出材料外条号 → 材料内问题正常作答，材料外明确拒绝"不能凭记忆给出条文"
- **无材料**：直接说"未检索到可用资料，不凭记忆作答"，并给出下一步（补充资料 / 说明关注点）

### 5.3 规模与配比

- 领域样本 500（展开后 ≈700）；replay：通用 300（带 think）+ tool 100（`/no_think`），沿用 M11 数据
- 领域 : replay ≈ 1.25 : 1，防遗忘（M8 教训：过拟合谷底在 epoch 2.5）
- 留出集按会话/按题抽 10%

### 5.4 生成与筛选

1. `gen_law_qa.py`：以真实条文为 context，用 base / M11 模型生成问答初稿
2. 人工核对：结论是否与条文一致、引用是否都在材料内、分档条件是否漏（法律内容必须人工过一遍，不许直接吃生成结果）
3. 验收题集与训练语料**分开生成**，防泄题

## 7. 验收：消融矩阵与指标

### 7.1 矩阵（temperature=0，同一知识库、同一 60 题集）

| 组 | 模型 | RAG | 验证什么 |
| --- | --- | --- | --- |
| A | base Qwen3-14B | 关 | 通用模型裸考基线 |
| B | base | 开 | RAG 带来的知识增益 |
| C | law-14b | 关 | **知识是否被错误塞进权重（应表现为"不知道"；答对=泄题告警）** |
| D | law-14b | 开 | 最终形态 |
| E | fkjs-14b | 开 | 对照：身份微调不带来领域增益 |

5 组 × 60 题 ≈ 300 次推理，本地 Q4 约 1–3 小时。

### 7.2 指标口径

人工判分；题集分布：事实分档 20 / 引用纪律 10 / 材料不足 10 / 越界 10 / 多轮 10。

- 结论正确率
- 引用准确率（引的编号都在材料里 **且** 引对了条）
- 材料外幻觉率（引出材料外的条号或内容；仅 RAG 开的组统计——A/C 组本无材料）
- 越界拒答率
- 闭卷拒答率（C 组）
- 引用格式（2026-10-17 加）：**标签一致性**（`[n]` 前抄的条文标签与该编号在材料里的标签是否一致）与 **引用无出处**（只写 `[n]` 不写标签）——这两项是「行内带出处」写法的兜底

### 7.3 判定标准（先写死，避免事后解释）

- D vs B：结论正确率 +≥20pp；引用准确率 ≥90%；材料外幻觉率 ≤5%
- C 组：闭卷拒答率 ≥90%，闭卷正确率 ≈0
- 通用能力不退化：tool 回归 8/8、身份 holdout 37/37

### 7.4 demo 剧本（4 幕）

1. A 组：编条文号 / 答错分档（一眼看出错）
2. B 组：有条文却不用、混入记忆内容
3. D 组：结论 + 分档 + 准确引用
4. 知识库改一条解释 → 重问即变（证明知识不进权重）

## 8. 风险与坑点

1. **两侧渲染不一致**（最高优先级）：训练 context 渲染必须调用服务端同一函数，改格式两侧同步
2. **阈值/预算重标定**：0.40 与 512 token 按原切块调定，按条切块后分布变化，需实测
3. **题集泄题**：验收题集与训练样本同源会让 C 组"闭卷答对"，直接毁掉核心结论
4. **记忆泄漏**：材料外条号在训练里重复出现会被记住 → 每条样本的"材料外编号"必须不同，并配足拒答样本
5. **Q4 量化口径**：A/B/C/D/E 全部 Q4_K_M，否则对比不公平
6. **max_seq / OOM**：法条 context 比 M8 样本长，max_seq 调大会 OOM（M8 已用 11.6/12GB）
7. **免责声明措辞单一**：每条都同一句会被过拟合 → 准备 3~4 种措辞
8. **并行冲突**：~~M11 正在改 `build_dataset.py` / `render_check.py`~~ **已解除（2026-10-17 M11 竣工）**；`data/`、`models/`、`config.MODELS` 的写入改为本方案自行负责
9. **召回的口语化缺口（2026-10-17 实测，已知限制，不做）**：纯稠密检索（bge-small-zh + top3 + 阈值）对法律术语问法可用，但口语问法 top-3 只有 **7/15 = 47%**——「我从公司离开了」召回第八十七条（应中三十七/四十六条）、「不给我交社保」召回第九条、「公司让我走人」召回第九十一条。漏召回在线上表现为「材料不足」，看起来像模型笨。**改进路径（未实施，接手者可任选）**：① 口语→术语映射表（50 条，纯数据）；② 多查询变体 + RRF 融合；③ LLM query 改写轮（每问多一轮推理）；④ 文档侧加白话摘要/关键词。demo 时不追求口语覆盖，提问用书面表述。注：实测还发现部分 miss 是 gold 标窄（一题应有多条可接受），重测需放宽 gold
