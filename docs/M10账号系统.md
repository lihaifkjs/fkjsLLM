# M10 账号系统（简单登录门）

> 状态：已竣工（2026-10-15） | 日期：2026-10-15
> 定位：项目收尾项。一/二期 PRD 中「多账号体系」均搁置（一期 §3.6 仅留 `AUTH_ENABLED` 占位），现降级为「简单登录门」落地，属范围变更，需同步 PRD 变更记录。

## 1. 范围决策（2026-10-15 已确认）

- **登录门，不做多账号**：登录后才能用，会话数据不按用户隔离
- **凭据配置文件写死**：不配 users 表、不动 SQLite 迁移链、不做注册/改密
- **内存 token**：服务重启后所有登录态失效，重新登录即可
- `AUTH_ENABLED` 默认 false，关闭时行为与现状完全一致

## 2. 设计

### 后端
- `config.py`：`AUTH_ENABLED`、`AUTH_USERS`（用户名→密码，可配多个）
- `POST /api/auth/login`：校验凭据 → 发随机 token，内存集合存有效 token
- 其余 `/api/*` 经统一依赖项校验 token（`Authorization: Bearer <token>`），无效返 401；静态文件与 login 除外

### 前端
- 登录页 + 路由守卫（无 token 跳登录），token 存 localStorage
- 请求拦截器统一带 token，401 自动跳回登录页
- mock 按新约定只留最小桩

### 待确认坑点（已闭环）
- ~~SSE token 传递方式~~：现有实现为 fetch + ReadableStream 手动解析（web/src/api/sse.ts），token 直接走 `Authorization` header，无 EventSource 限制。

## 3. 实现要点（2026-10-15 落地）
- 后端：`server/auth/`（login 签发 `secrets.token_urlsafe(32)` + 内存集合 + `require_auth` 守卫）；`server/api/auth.py` 两端点；`main.py` 业务路由统一挂 `Depends(require_auth)`；`config.py` 凭据默认 `admin:fkjs-admin`，可用 `AUTH_USERS="u1:p1,u2:p2"` 环境变量覆盖（避免真实密码入库）。
- 设计增量：新增 `GET /api/auth/status`（免鉴权），前端路由守卫据此决定是否启用登录门——后端未开 `AUTH_ENABLED` 时前端零感知。
- 前端：`utils/auth.ts`（token 存取/401 跳转，leaf 模块避免循环引用）/ LoginView / 路由守卫（enabled 状态按页面加载缓存一次）/ client.ts + sse.ts 注入 `Authorization` header 与 401 跳转 / mock 最小桩（enabled: false）。
- 401 跳转用 `window.location.href` 整页跳转（顺带清空路由守卫缓存）。

## 4. 验证记录
- 后端 curl 冒烟（`AUTH_ENABLED=1`）：status 免鉴权通 / 无 token 401 UNAUTHORIZED / 错误凭据 401 INVALID_CREDENTIALS / 正确凭据签发 token / 带 token 访问 params、model/status 200；默认不开关时无 token 直接 200。
- 前端：`npm run build`（vue-tsc + vite）通过；页面效果按 2026-10-14 规约不专门验证。

## 5. 明确不做
- 多账号数据隔离（sessions/messages 加 user_id）
- 注册、改密、权限
- 重启免重登（token 持久化/签名）
