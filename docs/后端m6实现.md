# M6 后端实现：参数实验场（experiments 存储 + lab 编排 + SSE 生成）

> 状态：已完成 | 日期：2026-10-10
> 上游：[M6开发计划.md](M6开发计划.md)（表结构 §3、批次 1 步骤 §4、决策记录 §7、风险坑点 §8）、[后端m5实现.md](后端m5实现.md)（观测口径）
> 范围：experiments/experiment_runs 两表与迁移、lab 编排模块、6 个实验端点、PROMPT_TOO_LONG 防护、互抢锁 409。

## 1. 实现要点

### 1.1 存储与迁移（`session_store/sqlite_store.py`、`base.py`）

- user_version 1→2：experiments / experiment_runs 两表 + `idx_runs_experiment` 索引写进 `_SCHEMA`（`IF NOT EXISTS`，新老库同路径覆盖），`_migrate` 只对 version<1 的一期老库补 M5 列，然后统一推版本号——v0/v1/新库三路径都收敛到 2
- experiment_runs 观测列与 messages 表 M5 口径逐字一致，但**没有 params_snapshot 列**——`params` 列（四参数 JSON）本身就是快照
- `Experiment` / `ExperimentRun` / `RunResult` dataclass 在 `base.py`（对齐 Message 的存放约定），docstring 接口清单同步补充
- CRUD：`create_experiment` 连 runs 同事务插入（seq=0/1/2，status=pending）；`start_run` 置 running 并清空上轮 error（重试场景）；`finish_run` 是唯一的终态回填入口（对齐 `update_message` 汇合模式）

### 1.2 参数校验（`params/presets.py`）

- 新增公共入口 `validate_run_params(patch)`：只允许 `RUN_FIELDS` 四项（temperature/top_p/top_k/max_tokens，决策 D）且缺一不可，范围规则复用 `_validate`（与全局参数同一份规则，不另抄）；非法抛 ValueError，api 层转 400 `INVALID_PARAMS`

### 1.3 实验编排（`lab/engine.py`，新增模块）

- 与 chat 平级（技术方案 §3.0）：直调 model_manager / session_store / params，不碰 HTTP
- `create_experiment`：组数 2–3 校验 → 逐组 `validate_run_params` → system prompt 取**创建时**全局值快照入 experiments 表（决策 D，保证实验间可比性）
- `run_generate`：404 检查 → busy 预检 → `start_run` → 组装 messages（system 快照 + 单条 user，单轮无历史不走滑窗，决策 F）；repetition_penalty 用全局当前值，四项采样参数用本组快照
- **`_wrap` 复刻 `chat/engine._wrap` 的 finally 汇合模式**（计划 §8 头号坑点）：done / stopped / error 三路径都经 `finish_run` 回填部分内容 + 全部观测字段；异常先记 error `{code, message}` 再 `raise` 交由 api 层转 error 帧
- **busy 预检双检**（实测踩坑）：`generate` 是惰性生成器，全局锁在首个 token 才占用，`status().generating` 覆盖不到 lab 侧并发起跑——故 `_active_run_id` 自锁 + `generating` 双检，命中抛 `GENERATION_BUSY`（全局 handler 转 409），run 保持原状态可重试（决策 E）。预检与首个 token 之间仍有理论竞态窗口，退化为流内 error 帧 `GENERATION_IN_PROGRESS`，chat 既有同款窗口
- **PROMPT_TOO_LONG**（步骤 4.4）：检查放 `_wrap` 内、token 迭代之前（此时锁未占用）；`count_tokens` 对 system 快照 + prompt 求和对比 `n_ctx - max_tokens`（content 级口径同 `fit_window`），超长抛 ServiceError → SSE error 帧 + run 落库 error
- **残留 running 纠正**（计划 §8）：`get_experiment_detail` 读路径把「status=running 但非当前活跃 run」纠正为 error `RUN_INTERRUPTED` 并落库，避免前端永久显示「生成中」

### 1.4 路由（`api/lab.py`，新增；`main.py` +2 行挂载）

- 只做 HTTP ↔ engine 转换；SSE 帧型与 chat 逐字一致（meta/token/done/error，done 带 usage+timing）
- 观测数据随详情接口全字段下发（决策 B，不开独立 observability 端点）；JSON 列（params/error/prompt_messages/prompt_seg_tokens）解析为对象
- 404 用 HTTPException detail 包装（对齐 M5 MESSAGE_NOT_FOUND 形状）；409 仍走全局 ServiceError handler

## 2. 接口增量

| 端点 | 说明 |
| --- | --- |
| `GET /api/experiments` | 列表（id / prompt 截前 50 字 / created_at，id 倒序） |
| `POST /api/experiments` | `{prompt, param_sets[2–3]}` → 详情（runs 为 pending） |
| `GET /api/experiments/{id}` | 详情：实验 + runs 全字段（含观测列，JSON 列已解析） |
| `DELETE /api/experiments/{id}` | 级联删 runs → `{"deleted": id}` |
| `POST /api/experiments/{eid}/runs/{rid}/generate` | SSE：meta `{experiment_id, run_id}` → token → done `{usage, timing}`；失败为 error 帧 |
| `POST /api/experiments/{eid}/runs/{rid}/stop` | → `{"state": "stopping"}` |

错误码清单：

| 码 | HTTP | 场景 |
| --- | --- | --- |
| `INVALID_PARAMS` | 400 | 组数非 2–3 / 字段非法 / 空 prompt |
| `EXPERIMENT_NOT_FOUND` / `RUN_NOT_FOUND` | 404 | 详情 / 删除 / generate / stop，含 run 不属于该实验 |
| `GENERATION_BUSY` | 409 | 互抢锁（决策 E），run 不置 running 可重试 |
| `MODEL_NOT_LOADED` | 409 | 预检（对齐 chat），run 不置 running |
| `NO_ACTIVE_GENERATION` | 409 | stop 非运行 run |
| `PROMPT_TOO_LONG` / `INTERNAL` / `GENERATION_IN_PROGRESS`（竞态） | SSE error 帧 | 推理期错误，run 落库 status=error + error JSON |

## 3. 验证方法

全程用临时库（`DB_PATH=/tmp/m6_*.db`），未碰 `server/data/app.db`；模型实测（CPU 版，max_tokens=32 短句）。

- **迁移三路径**：v0（一期库）→2、v1（M5 库）→2、新库直建，M5 列与老数据保留；CRUD 单元（建实验连 runs / start/finish 回填 / 重试清 error / 404 / 级联）脚本直测通过
- **curl 全流程**：3 组温度参数逐个流式完整 → 详情观测字段齐全，**seg 三段之和 = input_tokens**（三栏均 15）；run2/3 可见 KV 前缀复用（`prompt_eval_tokens=1`、prefill_ms=0、TTFT 4339ms→92ms，M5 口径预期）
- **stop 中断**：生成 14 token 后停止 → status=stopped，部分内容 + 观测字段 + finished_at 全部回填
- **互抢锁**：生成中并发第二栏 → HTTP 409 `GENERATION_BUSY`（被拒 run 保持 pending）；并发 chat → chat 侧既有 error 帧 `GENERATION_IN_PROGRESS`（未动）
- **PROMPT_TOO_LONG**：max_tokens=8000 压预算至 192 tokens → meta 帧后 error 帧，run 落库 error
- **错误路径**：400（越界/类型/未知字段/缺字段/组数/空 prompt）、404（详情/删除/generate/stop/run 跨实验）、409（卸载后 generate、stop 非运行 run）逐一实测；列表截 50 字、删除级联实测

## 4. 遗留

- busy 预检与首个 token 之间存在理论竞态窗口（退化为流内 error 帧而非 409），chat 同款，单用户场景可不处理
- PROMPT_TOO_LONG 的计数是 content 级近似（不含模板开销，同 `fit_window` 口径），临界值附近可能晚漏判；与 M5 遗留的滑窗计数问题同源，M6.5 一并评估
- KV 全命中时 `output_tokens` 出现 `max_tokens + 1`（n_eval+1 口径），与 chat 同源同口径，非 M6 新引入
- FastAPI 新版路由惰性物化（`app.routes` 为 `_IncludedRouter` 包装），静态枚举路由不可靠，路由验证须走真实 HTTP
- 批次 2（前端 `/lab` 页面）与批次 3（联调、tag `v0.6-m6-lab`）未开始
