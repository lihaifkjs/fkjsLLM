# M6 前端实现：参数实验场

> 状态：已完成 | 日期：2026-10-10
> 上游：[M6开发计划.md](M6开发计划.md)（批次 2/3）、[后端m6实现.md](后端m6实现.md)（数据契约）、[前端m5实现.md](前端m5实现.md)（观测口径基线）
> 硬约束遵守：SSE 帧协议与 chat 完全一致（meta/token/done/error）；观测数据随实验详情下发，不复用 useObservability 消息通道。

## 1. 数据流（核心设计）

```
LabView 编辑态（prompt + 2~3 组 RunParams）→ POST /experiments 创建（返回含 pending runs 的详情）
→ stores/lab.ts startQueue 串行队列：逐个 pending run 调 generateRun（POST SSE）
→ 流式 token 追加到 run.content；done/error/stopped 三路径收尾
→ 每个 run 结束后重拉 GET /experiments/{id} 详情回填观测全量字段（决策 B）
```

- `api/sse.ts`（新增）：`postSse`/`parseSseFrames`/`parseErrorBody` 公共封装，chat 与实验 generate 共用；EventSource 不支持 POST，统一 fetch + ReadableStream 手动分帧；`abort()` 只断本地读取，服务端中断走 stop 接口
- `stores/lab.ts`（新增）：串行队列状态机（决策 C：前端逐个发，后端不建队列）。`runOne` 用 Promise + `activeRuns` Map（handle + settle）统一三路径收尾；本地 abort 不触发 onDone/onError，由 settle 结束 promise 让队列继续
- `stopRun`：先 abort 本地流，再 POST stop 通知后端（竞态忽略），settle 落定 `stopped`
- `openExperiment` 兜底纠正：详情里 `running` 但本地无活动句柄（刷新/断连）→ 本地标 `error`（INTERRUPTED），防永久「生成中」

## 3. API 层与 mock

- `types.ts`：`RunParams`/`RunStatus`/`ExperimentSummary`/`ExperimentRun`（观测列与 M5 messages 口径一致）/`Experiment`（含创建时 `system_prompt` 全局快照，决策 D）/`CreateExperimentRequest`；SSE meta 帧加 `RunMeta{experiment_id, run_id}`；`LlmApi` 加实验 CRUD + `generateRun`/`stopRun`
- `client.ts`：chat 流重构到 sse.ts；实验端点直连；`parseErrorBody` 兼容 FastAPI 400 的 `detail` 包装与 409 顶层 `{code,message}` 两种形状
- `mock.ts`：实验持久化到 localStorage（`fkjsllm.mock.lab`）；按 temperature 三档选风格模板做差异化输出（教学对比）；观测自洽（seg 三段之和=input_tokens、decode=output×30ms）；`stopRun` 兜底把 running 纠正为 stopped

## 5. 遗留

1. **联调修复的 bug**：`createExperiment` 请求体曾用 `runs` 字段，后端契约为 `param_sets`，real 下 POST 422（mock 同名字段所以未暴露）。已改 `types.ts`/`stores/lab.ts`/`mock.ts` 三处对齐 `param_sets` 并重新构建通过
2. **契约缺口（未修）**：后端 `GET /experiments` 列表未下发 `run_count`（`server/api/lab.py`），前端 `ExperimentSummary` 与历史抽屉「N 组」依赖该字段，real 下显示 undefined。历史抽屉不在本次主干验证范围，待后端补字段或前端改展示
3. **停止/历史/互抢锁/刷新恢复 real 未验**：停止按钮在 mock 轮因 30ms 流式刷新导致元素引用失效未点中；real 轮按瘦身要求只验主干。`stopRun`/`retryRun`/409 GENERATION_BUSY 提示/刷新后 running 纠正均为代码路径就绪但未经真实模型实测
4. HTTP 层失败（409/404/模型未加载）时后端不改 run 状态，`runOne` 末尾的详情回填会把本地 error 冲掉——已在 lab.ts 把本地 error 结论写回刷新后的 run 对象（mock 409 场景验过）
5. mock 生成中逐 token 不持久化，刷新中断的 run 部分内容丢失（仅 mock 演示影响）；测试后浏览器 localStorage 有 `fkjsllm.mock.lab` 残留，需手动清理
6. 后端口径观察（非前端问题，记录备查）：max_tokens 48 时 output_tokens 落库 49（含 EOS 类计数差异）；实验间同前缀 prompt 会让 prompt_eval_tokens < input_tokens（KV 复用），观测区已如实展示
