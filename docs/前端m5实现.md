## 1. 数据流（核心设计）

观测数据不走消息对象，走独立通道：

```
抽屉打开 → pane 内 useObservability(message)（新增 composable）
  → message.id 为真实后端 id（正数）才调 GET observability
  → 失败/全 null → 静默降级到 frameStats（帧记录，仅本次会话内有效）
  → 再不行 → el-empty
```

- 生成中的消息观测数据尚未落库，自动走帧统计降级（实时 token/s 等既有行为保留）
- 历史消息（刷新后重载、帧记录已丢）由 observability 端点覆盖——M3 遗留的「该消息无统计数据」缺口补上了

## 3. API 层与 mock

- `types.ts`：`Observability`/`SegTokens`/`ParamsSnapshot`/`Timing`，done 帧加 `timing`；`LlmApi` 加 `getObservability(sessionId, messageId)`
- `client.ts`：新端点 GET；404 的 `detail` 包装由既有 `parseErrorBody` 兼容（m3 坑点同形状）
- `mock.ts`：`buildObservability()` 造自洽假数据（seg 三段之和 = input_tokens；多轮时 prompt_eval < input 模拟 KV 复用；done 帧 timing 与 observability 同源）；`generatingMessageId` 模拟「生成中未落库」时序；消息不存在抛 `MESSAGE_NOT_FOUND`

## 5. 遗留

1. 生成中打开抽屉后，done 完成不会自动重取观测数据（composable 只 watch message.id），重开抽屉即得服务端真值
2. 占比条百分比各自四舍五入，总和可能 99%/101%（视觉无影响）
3. mock 的 `params_snapshot` 反映当前参数而非逐消息历史快照（mock 无落库），仅影响 mock 演示
4. 本机无 node 工具链，本次构建用临时解压的 Node v22（/tmp/node-toolchain），需正式安装
