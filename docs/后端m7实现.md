# 后端 M7 实现说明：RAG 知识库

> 日期：2026-10-11 | 上游：[M7开发计划.md](M7开发计划.md)（决策 A–K）、[二期prd.md](二期prd.md) §6、[技术方案.md](技术方案.md) §5.3
> 范围：documents/chunks/retrievals 三表（user_version 4）+ sessions.rag_enabled / rag 模块（chunker/embedder/ingest/retriever）/ knowledge 三端点 / 检索注入编排与调用链观测

## 1. 实现要点

### 1.1 embedding 栈选型（批次 0 spike）

- **fastembed（onnxruntime）加载 BAAI/bge-small-zh-v1.5**，CPU。与候选 llama-cpp GGUF（CompendiumLabs 转换，f16/q8_0 已存 server/models/ 备用）对拍：Top-3 命中率持平（均 100%），fastembed 单条 embedding 快 4–10 倍（query 1–2ms vs 6–11ms），且权重自动下载缓存免手工管理
- 对拍余弦 0.93–0.95 未达 ≈1（两侧 pooling 均为 CLS，差异来自第三方 GGUF 转换与官方 ONNX 的数值差）——该 GGUF 不等价官方权重，用栈 A 需另行验证
- bge 两坑实证：两侧向量必须 L2 归一化（llama-cpp 出参范数 5–7 未归一化；fastembed 已归一化但 spike 证明该行为不可依赖，代码里幂等再归一化）；query 前缀对命中率中性，但**加前缀后域外 query 最高分一致更低**（0.29 vs 0.32），拉大了域内/域外间隔，故保留
- **阈值 0.40 依据**：域外 query 最高 0.32 / 域内最低真实命中 0.4463，有效区间 [0.32, 0.44]；计划候选 0.45 会误杀 0.4463 的真实命中。注意同域错误文档分数可达 0.52–0.60，阈值拦不住（small 模型分数压缩特性），靠 Top-K 兜底
- spike 脚本：`server/spikes/m7_embedding_spike.py`（网格）+ `m7_embedding_spike2.py`（域外取证/范数诊断），结果存同名 json

### 1.2 存储（session_store，user_version 3→4）

- 三表均 `_SCHEMA` 内 `IF NOT EXISTS`（迁移只推版本号）；sessions.rag_enabled 走 `_M5_COLUMNS` 同款 ALTER 清单（`_M7_SESSION_COLUMNS`，带列存在性检查，幂等）
- `retrievals.hits` 内嵌命中片段快照 JSON，不回联 chunks——文档删除后历史调用链仍可读（决策 H）；删文档级联 chunks、删会话级联 retrievals（`PRAGMA foreign_keys = ON` 原有）
- `Session` dataclass 加 `rag_enabled`；新增 `Document` / `Chunk` / `RetrievalInput` / `Retrieval` 与 CRUD（含 `get_all_chunks` 全表扫描、`get_retrieval_by_trigger` 仿压缩同款）

### 1.3 rag 模块

- `chunker.py`：固定窗口 500 字 + 重叠 50，`\n\n` 段落边界优先的纯函数
- `embedder.py`：fastembed 懒加载单例（双检锁），出参 L2 归一化（幂等保险）；独立 CPU 栈，不经过 model_manager、不碰生成锁；dim=512 实测与 schema 一致
- `ingest.py`：校验（.txt/.md、≤256KB、utf-8）→ 切块 → embedding → 落库；写库前完成全部可失败步骤，写库阶段异常补偿删文档行，保证失败无残留；embedding 用 `struct.pack('<512f')` 序列化（零 numpy）
- `retriever.py`：`search(query)`：query 加前缀 → embedding → `get_all_chunks()` 全表余弦（反序列化后幂等归一化，点积即余弦）→ 阈值 0.40 → 降序 Top-3；空库直接返回不做无谓 embedding；filename 经 `list_documents()` 建映射

### 1.4 检索注入编排（chat/engine.py + chat/context.py）

- `context.py` 新增 `RAG_PREFIX` 与 `render_rag_segment(hits, max_tokens, count_tokens)`：按分数降序累加，超 `rag_max_inject_tokens` 丢后续片段，一个都放不下返回 None；`fit_window` 加 `extra_system` 参数（固定不截断、位于 system prompt 之后、token 计入 budget）
- `engine._build_prompt` 策略分流**之前**执行 `_retrieve_rag`：trigger_message_id = 本轮 assistant 占位消息 id（`chat()` 先插占位再拼上下文，与压缩同窗口）；无命中也落库（hits=[]、injected_tokens=0）；全段 try/except 降级不注入不落库（决策 I）
- 注入顺序：system prompt → RAG 段 → 摘要段 → 历史 → 当前输入；`_build_summary_context` 加 rag_segment 参数：计入 total budget（注入挤压历史触发压缩属预期），主路径手工组装、兜底路径经 `extra_system` 传入

### 1.5 接口增量（api/）

- `api/knowledge.py`（新）：GET/POST/DELETE `/api/knowledge/documents`；400 `INVALID_FILE_TYPE`/`FILE_TOO_LARGE`/`INVALID_ENCODING`、404 `DOCUMENT_NOT_FOUND`（HTTPException detail 包装，同 observability 404 形状）；上传依赖新增 `python-multipart`（requirements.txt 已加，另有 `fastembed>=0.9`）
- `api/sessions.py`：PATCH 扩展部分更新 `{title?, rag_enabled?}`（全空 400 `EMPTY_UPDATE`）；GET 列表项与会话响应加 `rag_enabled`；observability 加 `retrieval` 两态字段：会话启用且有落库 → 完整记录（含无命中 hits:[]）；未启用/无记录 → null

## 4. 遗留与边界

- 摘要策略 + 检索 + 真实压缩触发三者叠加的路径未跑过（只验了 summary 策略下滑窗兜底路径）；开关关闭后历史消息 retrieval 一律 null（记录仍在库，遵循决策 H 字面语义，如需「有记录即展示」改 `_retrieval_payload` 判断顺序）
- 空文档（0 chunks）允许入库未拦截；重复上传同名文件不去重（计划决策）
- fastembed 首次加载需外网或预热 `~/.cache/fastembed`（直连 HF 不通时 `HF_ENDPOINT=https://hf-mirror.com`）；内网部署需随包携带缓存
- mock 简化：老消息的 retrieval 按当前开关状态重建（后端是按生成时快照），仅 mock 如此
