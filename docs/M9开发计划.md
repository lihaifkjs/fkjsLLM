# M9 开发计划：工具调用——网页搜索（路线 A）

> 状态：**已竣工（2026-10-15 验收通过）** | 日期：2026-10-14
> 上游：[二期prd.md](二期prd.md) §8、`server/spikes/tool_calling_baseline.json`（2026-10-09 基线：决策正确率 87.5%、格式成功率 100%）
> 范围（已确认）：**只做路线 A**（内置 `web_search`，不走 MCP）；搜索源 360（so.com）抓 HTML（DDG 不可达、Bing 反爬投毒，2026-10-14 两次改）；会话级开关；单次搜索（无链式）。

## 1. 目标

模型自主决策搜索 → 后端解析 `<tool_call>` 并执行 → 结果裁剪后拼回 → 生成最终回答。按会话开关（默认关）；tool_calls 落库供调用链展示；SSE 发 `tool_call` 事件让前端渲染「正在搜索…」；失败降级不阻断对话。

## 2. 现状要点

- spike 已确认：`create_chat_completion(tools=...)` 可用；tool call 以 `<tool_call>{json}</tool_call>` 文本混在 content 流中（llama-cpp 0.3.36 不走 `message.tool_calls` 字段）；开 `/no_think` 后输出形态干净（空 think 壳 + tool_call 块或直接正文）
- `model_manager.generate()` 需加 `tools` 透传参数；`prompt_render` 不传 tools 时统计口径有偏差（阶段 1 实测后定处理）
- 编排挂 `engine.chat()`：assistant 占位消息 id 作 `trigger_message_id`（retrievals 同款）；两轮推理各自 acquire 生成锁（压缩同款）
- 会话开关 / 观测快照表 / PATCH 部分更新 / TracePane 区块 / mock 最小桩，全部照抄 M7 先例

## 3. 存储（user_version 4→5）

```sql
CREATE TABLE tool_calls (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  trigger_message_id INTEGER NOT NULL,  -- 本轮 assistant 占位消息 id
  name TEXT NOT NULL,                   -- 本期恒 web_search
  arguments TEXT NOT NULL,              -- 模型输出的原始 arguments JSON
  query TEXT NOT NULL,                  -- 解析出的搜索词（解析失败为空串）
  status TEXT NOT NULL,                 -- success / search_error / parse_error
  results TEXT NOT NULL DEFAULT '[]',   -- JSON 快照 [{title, url, snippet, content}]
  inject_tokens INTEGER,                -- tool response token 数
  latency_ms REAL,
  error TEXT,
  created_at REAL NOT NULL
);
ALTER TABLE sessions ADD COLUMN tool_enabled INTEGER NOT NULL DEFAULT 0;
```

`results` 快照语义仿 retrievals：不回联外部状态，网页变了历史调用链仍可读。

## 4. 调用循环（chat 层）

新增 `server/tools/`：`parser.py`（`<tool_call>` 解析 + 流式前缀判别纯函数）、`search.py`（360 抓取 + 正文提取 + 裁剪渲染，阶段 1 定是否拆 `extract.py`）。chat → tools；tools 不碰 model_manager/session_store。

会话 `tool_enabled` 时：

1. `_build_prompt` 走现有路径不变；system prompt 尾部渲染期追加工具提示段（当前日期 + 可用工具，对齐 spike 措辞），不写回 params
2. **决策轮**：`generate(messages, params, tools=[WEB_SEARCH])`，当前 user 消息追加 `/no_think`。**流式前缀检测**：缓冲输出直到可判别——偏离 `<tool_call>` 前缀立即回吐转正常流式（普通回答体验不损）；命中则静默消费至 `</tool_call>`
3. 解析成功 → SSE `tool_call` 事件 `{name, query}` → 执行搜索（同步秒级）→ 裁剪 → 落库 tool_calls
4. **回答轮**：messages = 决策轮 prompt + assistant（tool_call 原文）+ `{role: tool, content: 裁剪结果}`（Qwen3 模板原生支持 tool 角色，阶段 1 验证）；**摘掉 tools 正常流式**产出最终回答
5. assistant 消息只落最终回答文本（tool_call 标记不入 messages 表）；usage/计时/prompt_messages 取回答轮

**裁剪**：每条正文截 `tool_page_max_chars`，总量超 `tool_inject_max_tokens` 按序丢后续结果；常量进 config.py，阶段 1 定值，不暴露面板。

**降级**：搜索网络异常 → `search_error`，错误描述作 tool response 喂回让模型说明；JSON 非法 → `parse_error`，原文回吐当普通文本（spike 合法率 100%，纯兜底）；均落库，对话不阻断。

## 5. 接口增量

- SSE 只加一个事件：`tool_call` `{ "name": "web_search", "query": "string" }`（开始搜索时发；回答轮首个 token 到达即中间态结束，不需要结束事件）
- `PATCH /api/sessions/{id}` 加 `tool_enabled?`；`GET /api/sessions` 列表项加字段
- observability 加 `tool_calls`：启用且有落库 → 记录对象；否则 null（仿 retrieval 两态）

## 7. 决策记录

- **A. 只做路线 A**（2026-10-14 已确认）；MCP client 不在本期
- **B. 搜索源 360（so.com）抓 HTML + 重试 + 降级**（2026-10-14 三改）：DDG 本机网络不可达 → 改 Bing，实测按 TLS/IP 反爬投毒（httpx/curl_cffi/连续请求的 curl 均拿到标题正确但结果无关的页面）→ 改 360。360 高频测试撞「访问异常页面」约一半（重试 2 次可挽回一部分），真实使用频率低会好转；仍失败则落 search_error 喂回模型说明。百度/搜狗反爬墙、searxng 公共实例不可达，均已排除
- **C. 会话级开关** `sessions.tool_enabled`，默认关（已确认，仿 rag_enabled）
- **D. 单次搜索无链式**（已确认）：决策轮搜一次，回答轮摘 tools 直接回答；模型想再搜可在下一轮用户消息再触发
- **E. 决策轮 `/no_think` + 流式前缀检测**：spike 证明这是输出可判别的前提；前缀缓冲保证普通回答流式不损、tool_call 标记不外泄。副作用：工具会话决策轮不展示思考过程
- **F. 观测与历史分离**：assistant 消息只落最终回答；tool_call 原文与搜索结果快照进 tool_calls 表；SSE 只加 `tool_call` 单事件
- **G. 降级不阻断**（同 M6.5/M7 精神）：搜索/解析失败均落库且对话继续

## 8. 风险与坑点

- **think 块干扰判别**：不开 /no_think 时 think 内容先于 tool_call 输出，前缀判别失效——故决策轮强制 /no_think
- **prompt_render 口径**：tools= 使模板多渲染工具定义段，不传 tools 时 input_tokens/seg_tokens 偏小——阶段 1 实测偏差后定 render_prompt 是否加 tools 参数
- **360 不稳定**：高频撞「访问异常页面」（测试期约 50%），重试 2 次 + search_error 降级是刚需；真实低频使用会好转
- **llama-cpp 版本敏感**：文本协议解析依赖 0.3.36 已确认行为，升级库需复测
- **停止时序**：搜索是同步网络请求不响应 stop_event（秒级可接受），回答轮可正常被 stop；行为写进实现说明
