# 后端 M6.5 实现说明：上下文摘要压缩

> 日期：2026-10-10 | 上游：[M6.5开发计划.md](M6.5开发计划.md)（决策 A–G）、[二期prd.md](二期prd.md) §5
> 范围：compressions 表（user_version 3）/ `context_strategy` 全局参数 / 摘要压缩编排 / observability 调用链字段

## 1. 实现要点

### 1.1 存储（session_store）

- 新表 `compressions`（`_SCHEMA` 内 `IF NOT EXISTS`，迁移只推 user_version 2→3），兼任压缩历史与当前生效摘要缓存：**会话当前摘要 = 该 session id 最大的一条**，sessions/messages 表不动
- 关键字段：`covered_upto`（增量游标，摘要覆盖到的最大 message id，单调不减）、`trigger_message_id`（触发压缩的 assistant 占位消息 id，关联调用链）、`prev_summary` / `source_messages` / `source_prompt`（压缩输入三件套，供展示）、观测列（M5 口径精简版）
- CRUD：`add_compression` / `get_latest_compression` / `get_compression` / `get_compression_by_trigger`；删会话 ON DELETE CASCADE

### 1.2 参数（params/presets.py + config.py）

- `SamplingParams` 加 `context_strategy: str = "sliding_window"`；`presets._validate` 加枚举校验（`CONTEXT_STRATEGIES`），非法值 400 走既有 `parseErrorBody` 兼容形状
- **坑点**：老 settings 存档 JSON 缺新字段会 KeyError——`get_params()`/`snapshot()` 改为 `data.get(f.name, 默认值)` 回退
- 压缩常量（spike 定值）在 `Config`：`summary_keep_rounds=4` / `summary_max_tokens=512` / `summary_temperature=0.2`

### 1.3 摘要策略编排（chat/engine.py + chat/context.py）

- 纯函数在 `context.py`：`split_overflow`（切点对齐 user 边界，保留段以 user 开头）、`render_summary_request`（压缩模板 + ` /no_think` 软开关）、`strip_think`、`render_source`；`fit_window` 未动
- `engine._build_prompt` 按 `params.context_strategy` 分流；summary 路径 `_build_summary_context`：
  1. 裸 content 口径计数（与滑窗一致），未超 budget（`n_ctx − max_tokens`）不动作
  2. 超限且历史 > N 轮 → 溢出段中 `id > covered_upto` 的为新增待压缩；无新增则复用既有摘要
  3. 有新增 → `_run_compression`：独立一次 `model_manager.generate`（串行、消费完迭代器），落库 compressions，返回摘要
  4. 最终上下文 = system prompt + 摘要段（独立 system 消息，`SUMMARY_PREFIX` 前缀可辨识）+ 最近 N 轮
- **双兜底**：压缩后仍超 budget → 对 N 轮再走 `fit_window`；压缩异常/被停止/空摘要 → 返回 None 整体降级滑窗，对话不中断
- 压缩失败时不落 compressions 记录（下次超限会重试同样的新增段，幂等）

### 1.4 接口增量（api/sessions.py）

- `GET /sessions/{sid}/messages` **契约变更**：响应包一层 `{messages, summary_covered_upto}`；游标仅在当前策略为 summary 且会话有摘要时非空（切回滑窗标识即消失，记录保留可回切）
- observability 端点加 `compression` 三态字段：本轮触发 → 完整记录（含压缩前 prompt / 摘要 / token 对比 / 计时）；复用 → `{triggered: false, active_id}`；无 → null

## 2. think 块处理（spike 结论）

- `llama-cpp-python 0.3.36` 的 `create_chat_completion` **不支持 `chat_template_kwargs`**（TypeError）——M5 spike 的 enable_thinking 路线不可用
- user 内容尾加 ` /no_think`（Qwen3 模板软开关）有效：33 token / 7.2s vs 对照 128 token / 13.3s；产出空 `<think></think>` 壳由 `strip_think` 剥掉
- 压缩 prompt 不带会话 system prompt，固定低 temperature（0.2）

## 3. 遗留与边界

- **压缩期间被 stop**：压缩占着全局生成锁时用户按停止，打断的是压缩调用；当前按 `result.stopped` 降级滑窗后主生成仍会开始（stop_event 已消费）——体验瑕疵，遗留
- **锁窗口**：压缩结束与主生成 acquire 之间可被并发请求插入（决策 D 接受）；局域网单用户场景无碍
- **token 计数双口径**：触发判断用裸 content（同滑窗），展示用渲染口径（含模板开销），并存属预期
- mock 简化：老消息的观测按当前策略重建（后端是按生成时快照落库的），切策略后看老消息 trace 会与当初实际不符——仅 mock 如此
