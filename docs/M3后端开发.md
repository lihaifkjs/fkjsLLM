## 3. 批次 1：SQLite 持久化 + 会话 CRUD

| 步骤 | 文件 | 内容 |
| --- | --- | --- |
| 3.1 | `server/session_store/base.py`（新增） | dataclass（`Session`、`Message`）+ 类型化接口：`create_session / list_sessions / rename_session / delete_session / add_message / get_messages / get_context / get_setting / set_setting`，只定义不实现 |
| 3.2 | `server/session_store/sqlite_store.py`（新增） | 按技术方案 §4 建三表（sessions / messages / settings）；线程安全（生成在工作线程，连接 `check_same_thread=False` + 锁） |
| 3.3 | `server/config.py` | 增加 db 路径配置（`server/data/app.db`），`.gitignore` 排除 |
| 3.4 | `server/chat/engine.py`（改造） | 内存态 → 调 session_store；流程不变：null 建会话 → 存用户消息 → 生成 → 存助手消息（停止也落库） |
| 3.5 | `server/api/sessions.py`（新增） | §3.2 五个端点：列表（updated_at 倒序）/ 新建 / 取消息 / 重命名 / 删除（级联）；错误码沿用 409 + `SESSION_NOT_FOUND` |
| 3.6 | `server/main.py` | 挂载 sessions 路由 |
| 3.7 | 验证 | curl 全流程：建会话 → 多轮对话 → **重启后端** → 列表/历史还在 → 重命名 → 删除级联删消息 |

约束（技术方案 §1.1）：只允许 `chat`/`params` 调 `session_store`；`api` 不直接碰 SQLite 实现类以外的存储细节。

## 4. 批次 2：参数接口 + 滑窗截断

| 步骤 | 文件 | 内容 |
