# 前端 M4 实现（web/）

> 状态：M4 已完成（mock 模式 + 模拟手机视口实测通过），真机局域网联调待 Windows 部署后验收 | 日期：2026-10-08
> 配套文档：[前端m4开发.md](前端m4开发.md)（计划）、[prd.md](prd.md) §3.5、上游 [前端m3实现.md](前端m3实现.md)
> 范围：纯前端响应式改造，后端零改动

## 1. 已做什么

### A. 断点统一

- 新增 `src/composables/useIsMobile.ts`：`MOBILE_BREAKPOINT = 768` + `matchMedia` 侦测（卸载时移除监听）；CSS 媒体查询无法引用 JS 常量，各组件 `@media (max-width: 768px)` 处均注释标注与该常量同源

### B. 会话列表抽屉化（PRD 3.5 核心）

- `ChatView.vue`：顶栏左侧汉堡按钮（仅移动端渲染，Menu 图标），打开 `el-drawer`（`direction="ltr"`，260px）；桌面侧栏从 CSS 隐藏改为 `v-if="!isMobile"`（JS/CSS 断点同口径）
- 抽屉内复用 `SessionList`，桌面侧栏与移动抽屉共用同一组件，行为一致（生成中拦截切换/删除/新建）
- `SessionList.vue` 新增 `selected` emit：选中 / 新建成功后 `ChatView` 自动关闭抽屉
- 操作图标（重命名/删除）原 hover 才显示，移动端无 hover：`@media` 下常显

### C. 软键盘与视口适配

- `ChatView` 高度 `100vh` → `100dvh`（vh 兜底在前）：iOS 软键盘弹出时布局随可视区收缩
- `index.html` viewport 加 `viewport-fit=cover`；输入区 `padding-bottom: calc(.. + env(safe-area-inset-bottom))` 适配 iPhone 底部横条
- `ChatInput.vue` 输入框加 `enterkeyhint="send"`（手机键盘回车键显示「发送」）

### D. 小屏布局细节

| 位置 | 改法 |
| --- | --- |
| ChatView 顶栏 | 标题 `flex:1 + min-width:0` + 省略号截断；小屏 header 内边距与右侧间距收窄 |
| ModelStatusBar | ≤768px 隐藏「显存 xxx MB」文本与加载中长提示（仅显示状态 tag + 按钮） |
| ParamsView / DebugDrawer | ≤768px 抽屉宽度 100%（桌面保持 420px / 480px） |
| MessageBubble | ≤768px 气泡 max-width 78% → 88% |
| 消息区/输入区 | 小屏 padding 24px → 12px |

## 2. 验证结果（2026-10-08，mock 模式）

- `vue-tsc -b && vite build` 通过，零错误（2MB chunk 警告为 M2 已知 hljs 体积问题）
- 本机无 Node，`ELECTRON_RUN_AS_NODE=1` 借用 Kimi Code 内置运行时（Node v24.18.0）跑 vue-tsc/vite
- 模拟手机视口（375×812，touch + mobile UA）逐项实测：
  1. 侧栏不显示，汉堡按钮打开抽屉 ✅
  2. 抽屉内选中会话 → 抽屉自动关闭 + 历史消息回填 ✅
  3. 抽屉内新建（自动关抽屉）/ 重命名（弹窗宽度适配）/ 删除（确认弹窗 → 列表移除）✅，操作图标无 hover 常显 ✅
  4. 加载模型 → 发消息 → 流式渲染、代码高亮、上下文占用状态行（121/6144）✅
  5. 参数抽屉全屏（预设/滑块/保存可用）、调试抽屉全屏（标签页 + SSE 帧列表）✅
  6. 长会话标题顶栏省略号截断，不挤爆布局 ✅
- 桌面视口（1440px）回归：双栏布局、参数抽屉 420px、会话列表 hover 行为均与 M3 一致 ✅
- **代码走查项（模拟器不可验）**：dvh 随软键盘收缩、enterkeyhint、safe-area——留真机验收
