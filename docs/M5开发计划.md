## 1. 目标

- 每条 assistant 消息可查看：完整模型输入（按角色着色）、分段 token 统计（system/历史/当前）、TTFT/prefill/decode 分段耗时、该消息的生效参数快照（含默认值来源标注）
- 观测数据随消息落库，**历史消息刷新后同样可查**（现状帧记录仅存内存，历史消息一律无数据）
- usage 从近似值升级为精确值（M2 遗留坑点）

## 2. 现状盘点（2026-10-09 调研结论）

**后端**：
- messages 表已有 `input_tokens / output_tokens / params_snapshot` 三个预留列（一期 PRD §3.7）；`params_snapshot` 恒 NULL；`GET /sessions/{id}/messages` 刻意不返回 token 字段（后端m3实现 §2.3）
- usage 现状两处近似：`manager.py:157-159` 逐条 tokenize content 求和（**不含 chat template 开销**）；`output_tokens` 按收到 chunk 数计数
- prompt 渲染发生在 llama-cpp 内部（gguf 元数据 Jinja2 模板），渲染结果从未落地；无公开 API 返回渲染文本
- llama-cpp-python 0.3.36 流式**不支持** usage 回传（无 `stream_options`）；但 ctypes 层暴露 `llama_perf_context`（`t_p_eval_ms / t_eval_ms / n_p_eval / n_eval`），是精确 usage 与分段计时的数据源
- 计时埋点位置清晰：`_iterate` 循环前 t0、首个非空 text t1（TTFT）、循环退出 t2；`_gen_lock` 保证单路生成，perf 计数无并发干扰；`verbose=False` 需手动 `_ctx.reset_timings()`
- 加列需要迁移：现有 `server/data/app.db` 已按旧 schema 建好，`CREATE TABLE IF NOT EXISTS` 不会加新列

**前端**：
- 抽屉机制 = `DebugDrawer.vue` 的 `TABS` 配置数组 + `<component :is>`，pane 统一收 `{title, message}` prop；三个占位 `PlaceholderPane`；完全符合「加配置 + 写组件」
- 现有 TokensPane/PerfPane 数据源是**客户端帧时间戳**（`stores/debug.ts` 内存 Map + `utils/frameStats.ts`），含网络延迟且刷新即丢；两组件注释均已预留「后端带数据后在此加行」扩展位
- `ChatMessage` 契约类型不掺调试数据（`stores/debug.ts` 设计边界），M5 需遵守
- 参数默认值/预设在 `settings.ts` / `mock.ts` / `ParamsView.vue` 三处重复定义；前端发消息不传参，无法自行得知某条消息的生效参数——快照必须由后端落库
- done 帧扩展需同步改 `types.ts` / `client.ts` / `mock.ts` 三处

## 7. 决策记录（2026-10-09 已确认）

- **A. 观测数据暴露方式**：独立 `GET /api/sessions/{sid}/messages/{mid}/observability` 端点，不扩展 messages 列表出参
- **B. Prompt 存储**：`prompt_text`（渲染原文）与 `prompt_messages`（messages JSON）都存，着色视图/原文视图各取所需
- **C. 输入 token 口径**：`input_tokens` 用渲染后 tokenize（账单口径）；同时落库 `prompt_eval_tokens`（`n_p_eval`，本轮实际算力，KV 前缀复用下会小于账单口径）作教学展示
- **D. 错误码**：消息不存在用 404 `MESSAGE_NOT_FOUND`（首个 404 业务码，区别于既有 409 约定）
- **E. 分段统计口径**：system / 历史 / 当前三段，前缀差分法计算（渲染次数 = 消息条数，受滑窗限制可接受）

## 8. 风险与坑点

- **私有 API 依赖**：`_ctx` / `Jinja2ChatFormatter` / `llm.metadata` 均为 llama-cpp-python 内部实现，结论绑定 0.3.36；升级库时必须重验（新版若支持 `stream_options.include_usage` 可简化 usage 链路）
- **渲染一致性**：自建渲染若与 llama-cpp 内部渲染不一致，prompt 预览即失真——3.2 落地后先与 verbose 日志/非流式 usage 对拍一次
- **done 帧扩展**影响 `types.ts`/`client.ts`/`mock.ts` 三处，遗漏任一处 mock/real 行为不一致
- **mock 默认值三处重复**（settings.ts / mock.ts / ParamsView.vue），来源标注逻辑以后端 `params_snapshot` 为准，前端三处不动（M5 不收敛，记入遗留）
- **前缀差分假设**：渲染 messages[:k] 是渲染 messages[:k+1] 的前缀（Jinja 模板追加式成立）；若模板有尾部总结结构需改为逐条渲染方案，3.2 验证时确认
  - **2026-10-09 已命中并修复**：Qwen3 模板对「最后一次提问之前」的 assistant 消息会剥掉 think 块，直接前缀差分出现负值；方案为按模板同款逻辑先归一化再差分（`_normalize_messages`，`prompt_render.py`），spike 与滑窗场景均已验证
- **stop 中断路径**：t2/perf 读取在循环 break 后仍有效，finally 汇合点统一回填，验证时覆盖（3.5 已含）
