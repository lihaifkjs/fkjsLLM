## 1. 已做（M2 范围）

| 模块 | 文件 | 内容 |
| --- | --- | --- |
| config | `server/config.py` | 模型路径、`n_gpu_layers`、`n_ctx=8192`、默认采样参数（Qwen3 官方推荐值：temp 0.7 / top_p 0.8 / top_k 20 / rep_penalty 1.05 / max_tokens 2048），支持 `MODEL_PATH`、`N_GPU_LAYERS` 环境变量覆盖 |
| model_manager | `server/model_manager/manager.py` | 模型单例 + 五态状态机；加载/卸载在工作线程执行；全局生成锁（同时仅一路生成）；逐 token 检查停止信号 |
| chat | `server/chat/engine.py` | **内存态会话**（重启即丢，SQLite 留待 M3）；上下文拼接（system → 历史 → 当前输入）；停止后部分结果保留；会话标题取首条消息前 20 字 |
| api | `server/api/chat.py`、`server/api/model.py` | 对话 SSE + 停止、模型三接口；业务错误统一 409 |
| 入口 | `server/main.py` | FastAPI app；若 `web/dist` 存在则自动托管前端静态文件 |

已实测通过：加载（约 10s）→ SSE 流式 → 中途停止（部分结果入库）→ 生成中卸载被拒 → 卸载后 chat 被拒 → 多轮上下文正确（第二轮 input_tokens 5→193，模型记得第一轮内容）。

## 3. 接口说明（前端联调用）

Base URL：开发环境 `http://<PC_IP>:8000`（vite 代理到 8000），生产同源。
**约定：所有业务错误返回 HTTP 409 + `{"code", "message"}`**；参数格式错误返回 400/422。

### 3.1 模型加载开关

```
GET  /api/model/status
  → {"state": "unloaded|loading|loaded|unloading|error",
     "vram_used_mb": null,        // CPU 版恒 null，CUDA 版后补
     "error": null,               // state=error 时的原因
     "generating": false}         // 扩展字段：是否生成中（技术方案 3.4 之外新增）

POST /api/model/load    → {"state": "loading"}   // 异步，轮询 status 直到 loaded
POST /api/model/unload  → {"state": "unloading"} // 生成中调用返回 409 GENERATION_IN_PROGRESS
```

前端策略（技术方案 §5.4）：每 5s 轮询 status + 开关操作后立即刷新；`state != loaded` 时禁用输入框；`loading` 时显示加载提示（约 10s，勿判卡死）。

### 3.2 对话（SSE）

```
POST /api/chat
请求: {"session_id": null, "content": "你好"}   // null=新建会话；追问填已有 id
Content-Type: application/json
响应: text/event-stream，事件序列：
```

| event | data | 说明 |
| --- | --- | --- |
| `meta` | `{"session_id":1,"user_message_id":1,"assistant_message_id":2,"title":"你好"}` | 首帧；`session_id` 用于后续追问与 stop |
| `token` | `{"text":"..."}` | 逐 token，直接拼接到当前气泡 |
| `done` | `{"usage":{"input_tokens":5,"output_tokens":175}}` | 正常结束（含被 stop 截断，部分结果已入库） |
| `error` | `{"code":"...","message":"..."}` | 失败，流随即关闭 |

帧格式为标准 SSE：`event: <名>\ndata: <JSON>\n\n`。
**注意 EventSource 不支持 POST，须用 `fetch` + ReadableStream 手动解析**（技术方案 §5.4）。

```
POST /api/chat/stop
请求: {"session_id": 1}  → {"state":"stopping"}
该会话无生成任务时 409 NO_ACTIVE_GENERATION
```

### 3.3 错误码表

| code | 触发场景 |
| --- | --- |
| `MODEL_NOT_LOADED` | 未加载/加载中调 chat |
| `GENERATION_IN_PROGRESS` | 生成中再发 chat、生成中卸载 |
| `NO_ACTIVE_GENERATION` | 停止一个没有生成任务的会话 |
| `SESSION_NOT_FOUND` | session_id 不存在 |
| `INVALID_STATE` | 非法状态迁移（如重复 load） |
| `EMPTY_CONTENT` | content 为空或纯空白（400） |

## 4. 前端必须知道的坑点

1. **会话是内存态**：后端重启后所有会话消失。前端拿到 `SESSION_NOT_FOUND` 应引导用户新建会话。
2. **Qwen3 输出含 `<think>...</think>` 思考块**：会直接混在 token 流里。已定方案：主界面折叠展示 + 调试抽屉看原始帧（见 前端m2实现.md §2）。
3. **`usage.input_tokens` 是近似值**：流式接口不返回 prompt token 数，后端逐条 tokenize 消息内容求和，不含 chat template 开销。做「上下文超限提示」可用，别当精确值。
4. **全局单路生成**：A 设备在生成时，B 设备发 chat 会收 409。前端应对该错误码提示「正在生成中，请稍后」。
5. **done 帧不代表没被停止**：被 stop 的流也以 done 收尾（部分结果），前端无需区分；想区分可看是否收到过 stop 响应。
6. **curl 传中文会报 parsing error**：Windows 终端编码问题，与后端无关；浏览器 fetch 无此问题。

## 5. 运维

```bash
# 安装（CPU 版，当前）
cd server
pip install -r requirements.txt
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu

# 启动（监听局域网，手机浏览器直接访问 http://<PC_IP>:8000）
python -m uvicorn main:app --host 0.0.0.0 --port 8000

# 接口文档（Swagger）
http://127.0.0.1:8000/api/docs
```

**切换 CUDA 版**（GPU 推理，约快 10 倍）：需先装 CUDA Toolkit + MSVC Build Tools + cmake，然后：

```bash
set CMAKE_ARGS=-DGGML_CUDA=on
pip install llama-cpp-python --force-reinstall --no-cache-dir
set N_GPU_LAYERS=-1   # 或改 config.py 默认值；4070 Ti 显存紧张时可改 32/40 层
```

业务代码零改动。

## 6. 验证方法（回归用）

```bash
# 1. 未加载时 chat 应 409
curl -N -X POST http://127.0.0.1:8000/api/chat -H "Content-Type: application/json" -d '{"session_id":null,"content":"hi"}'
# 2. 加载并轮询至 loaded
curl -X POST http://127.0.0.1:8000/api/model/load
curl http://127.0.0.1:8000/api/model/status
# 3. 流式对话（中文须存 UTF-8 文件用 --data-binary @file，见坑点 6）
# 4. 生成中：unload 应 409；stop 应立即收尾并保留部分结果
# 5. 追问（带 session_id）应记得上文
# 6. unload 后 status=unloaded，chat 再次 409
```
