## 1. 模块划分

### 1.1 后端（server/）

| 模块 | 职责 | 对外接口 | 依赖 |
| --- | --- | --- | --- |
| **api** | FastAPI 路由、SSE 封装、静态文件托管；只做 HTTP ↔ 内部调用转换，不含业务逻辑 | HTTP REST + SSE | chat、session_store、params、model_manager |
| **model_manager** | 模型实例单例、加载/卸载状态机、流式推理、停止信号 | `load() / unload() / status() / generate() / stop()` | config |
| **chat** | 上下文拼接、滑窗截断、重新生成/编辑重发的消息裁剪 | `chat() / stop() / regenerate() / edit_and_resend()` | model_manager、session_store、params |
| **session_store** | SQLite 读写（sessions / messages / settings） | `SessionStore` 类型化接口，SQLite 为实现类，换库只换实现 | config |
| **params** | 推理参数读写、预设、system prompt 模板 | `get() / save()` | session_store（settings 表） |
| **config** | 配置加载：模型路径、n_gpu_layers、n_ctx、端口、AUTH_ENABLED | 纯数据类 | 无 |

约束：`api` 唯一知道 HTTP；`chat` 不知道存储细节；`model_manager` 不知道会话与参数。

### 1.2 前端（web/）

| 模块 | 职责 | 通信约定 |
| --- | --- | --- |
| **api/client** | 唯一发起 HTTP/SSE 处，统一错误处理 | 组件禁止直接 fetch |
| **stores/**（Pinia） | `session`（列表+当前消息）、`model`（状态机镜像）、`settings`（参数） | 共享状态唯一来源 |
| **composables/useChatStream** | SSE 生命周期、逐 token 追加、中断、完成落库 | 聊天流唯一入口 |
| **views/** | ChatView、ParamsView、ModelControl | 组合 components + stores |
| **components/** | MessageBubble、ChatInput、SessionList、DebugDrawer（3.7 预留空壳） | props / emits |
| **router** | 路由 | — |

## 3. 接口契约

### 3.0 通信关系总览

| 协议 | 通信双方 | 形式 | 数据格式 |
| --- | --- | --- | --- |
| P1 | **浏览器 ↔ 后端 api 模块**（前端 api/client.ts 是唯一发起方） | HTTP REST + SSE，局域网 TCP | JSON（3.1–3.4 定义） |
| P2 | **api ↔ chat** | 进程内 Python 函数调用 | DTO：`ChatRequest(session_id, content)`；返回 token 迭代器 + 元信息 |
| P3 | **chat ↔ model_manager** | 进程内 Python 函数调用 | DTO：`GenerateRequest(messages, sampling_params)` → token 迭代器；`stop_event` 传递停止信号 |
| P4 | **chat / params ↔ session_store** | 进程内 Python 函数调用 | `SessionStore` 类型化接口（CRUD + `get_context(session_id)`），入出参为 dataclass |
| P5 | **api ↔ model_manager**（模型三接口） | 进程内 Python 函数调用 | `load() / unload() / status()`，status 返回状态枚举 + 显存数据 |
| P6 | **前端内部**：组件 ↔ stores ↔ composables | 进程内（浏览器 JS） | Pinia state/actions；组件间 props/emits |

依赖方向（谁允许调谁）：P1 是唯一的跨进程协议；后端内部各模块只准调用比自己更底层的模块——api 可直调 chat、params、session_store、model_manager，chat 可直调 model_manager 与 session_store，params 可调 session_store；禁止反向调用（下层调上层），禁止 chat 绕过 model_manager 直接碰模型实例、api 绕过 chat 自行拼上下文。

> 注：后端内部通信是函数调用而非网络协议，但同样受接口签名约束——这就是 1.1 节「模块只依赖接口」的含义；若未来模块拆成独立进程/服务，P2–P5 可直接替换为 HTTP 而调用方代码不改。

调用关系图（箭头 = 调用方向，只能上层调下层；P1–P5 对应上表协议编号）：


### 3.1 对话

**POST /api/chat** —— SSE 流
请求：`{ "session_id": number|null, "content": "string" }`（session_id 为 null 时新建会话）
SSE 事件序列：

| event | data | 说明 |
| --- | --- | --- |
| `meta` | `{ "session_id": n, "user_message_id": n, "assistant_message_id": n, "title": "string" }` | 流开始，首帧下发 |
| `token` | `{ "text": "string" }` | 逐 token 推送 |
| `done` | `{ "usage": { "input_tokens": n, "output_tokens": n } }` | 正常结束 |
| `error` | `{ "code": "string", "message": "string" }` | 失败，流随即关闭 |

**POST /api/chat/stop**：`{ "session_id": n }`，中断当前生成，部分结果保留入库。
**POST /api/chat/regenerate**：`{ "session_id": n }`，删除最后一条 assistant 回复并按原上下文重生成（走同一 SSE 格式）。
**PUT /api/sessions/{id}/messages/{mid}**：编辑用户消息并截断其后所有消息；之后由前端再调 `/api/chat` 重发（编辑与重发分两步，语义更清晰）。

### 3.2 会话

- `GET /api/sessions` → `[{ "id", "title", "updated_at" }]`，按 updated_at 倒序
- `POST /api/sessions` `{ "title"? }` → 会话对象
- `GET /api/sessions/{id}/messages` → `[{ "id", "role", "content", "created_at" }]`
- `PATCH /api/sessions/{id}` `{ "title" }`（重命名）
- `DELETE /api/sessions/{id}`（级联删消息）

### 3.3 参数

- `GET /api/params` → `{ "temperature", "top_p", "top_k", "repetition_penalty", "max_tokens", "system_prompt", "preset" }`
- `PUT /api/params`：同结构写回；服务端校验范围（temperature ≥ 0 等），预设切换时服务端展开为具体值

默认值：`temperature 0.7, top_p 0.8, top_k 20, repetition_penalty 1.05, max_tokens 2048, system_prompt ""`（对齐 Qwen3 官方推荐）。
内置预设：精确 `{0.1, 0.5, 10, 1.05}` / 平衡 `{0.7, 0.8, 20, 1.05}` / 创意 `{1.0, 0.9, 40, 1.05}`。

### 3.4 模型加载开关

- `GET /api/model/status` → `{ "state": "unloaded|loading|loaded|unloading|error", "vram_used_mb": n|null, "error": string|null }`
- `POST /api/model/load` / `POST /api/model/unload` → `{ "state": "..." }`

非法迁移（如生成中卸载、重复加载）返回 `409` + `{ "code", "message" }`。

## 4. 数据存储（SQLite）

```sql
CREATE TABLE sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL DEFAULT '新会话',
  created_at REAL NOT NULL,
  updated_at REAL NOT NULL
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  role TEXT NOT NULL CHECK (role IN ('user','assistant','system')),
  content TEXT NOT NULL,
  created_at REAL NOT NULL,
  -- 以下为可观测性预留字段（一期恒为 NULL，见 PRD 3.7）
  input_tokens INTEGER, output_tokens INTEGER, params_snapshot TEXT
);

CREATE INDEX idx_messages_session ON messages(session_id, id);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL  -- JSON 字符串
);  -- 存推理参数与 system prompt 模板
```

## 5. 关键实现要点

### 5.1 模型加载与 GPU offload

- llama-cpp-python 参数：`n_gpu_layers=-1`（全部层上 GPU），`n_ctx=8192`，`verbose=False`
- 4070 12GB 估算：权重约 9GB + KV cache（8192 ctx）约 1.3GB ≈ 10.5GB，可承载；若启动 OOM，配置项降级 `n_gpu_layers`（如 32/40 层）
- 加载在独立线程执行，避免阻塞事件循环；状态机管理迁移：`unloaded→loading→loaded→unloading→unloaded`，非法迁移拒绝
- `unload` 析构 Llama 实例并 `gc` + 释放显存；生成中拒绝卸载（409）

### 5.2 流式生成与停止

- 生成跑在工作线程，`model_manager.generate()` 返回 token 迭代器；api 层用 SSE 逐帧推送
- 停止：置 `stop_event`，迭代循环每 token 检查并跳出（当前 token 会完整返回后停止，可接受）
- 全局生成锁：同一时刻仅允许一路生成（PRD 非功能需求），并发请求返回 409

### 5.3 上下文管理

- 拼上下文顺序：system prompt（若配置）→ 历史消息 → 当前输入
- 滑窗：总 token 数超 `n_ctx - max_tokens` 时，从最早的 user/assistant 对开始丢弃，并在调试抽屉（二期）可观测；一期仅返回 `usage.input_tokens` 供前端做超限提示

### 5.4 前端要点

- EventSource 不支持 POST，SSE 用 `fetch` + ReadableStream 手动解析，封装在 `useChatStream`
- 模型状态轮询：`GET /api/model/status` 每 5s 一次 + 开关操作后立刻刷新；未加载/加载中输入框禁用
- 移动端：Element Plus 断点适配，会话列表抽屉化（el-drawer）

### 5.5 部署

```bash
# 后端（开发）
cd server && pip install -r requirements.txt && uvicorn main:app --host 0.0.0.0 --port 8000
# 前端（开发）
cd web && npm install && npm run dev   # 代理到 :8000
# 生产：web 下 npm run build，server 托管 web/dist
```

## 6. 验证方法

1. M1：curl 验证 `/api/model/load` 后 `/api/chat` 流式返回完整
2. 停止：流式中途调 `/api/chat/stop`，确认立即中断且部分消息入库
3. 卸载后再 chat，返回明确错误而非 500
4. 会话：删除会话后消息级联删除；编辑消息后其后消息被截断
5. 前端：桌面 Chrome + 手机同局域网浏览器各过一遍主流程
